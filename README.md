# 围之象棋 · Xiangqi-Go

中国象棋与围棋融合的原创网页棋类游戏。包含联机大厅、同屏双人和人机对战。无第三方运行依赖，使用 Node.js HTTP / SSE、原生 JavaScript、SVG 棋盘和 Web Worker。

## 快速上手

### 1. 本地直接运行

安装 Node.js 22 或更高版本后，在项目根目录运行：

```bash
npm start
```

然后在浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173) 。不要直接双击 `index.html` 打开，前端 ES 模块、Web Worker 和联机接口都需要通过 HTTP 服务加载。

运行自动化测试套件：

```bash
npm test
```

### 2. Docker 运行

```bash
docker compose up -d --build
```

服务启动后同样访问 `http://localhost:5173`。详细的多环境部署和 Nginx 反向代理配置见 [DEPLOY.md](DEPLOY.md)。

## 页面与对局入口

- 默认进入主菜单，选择联机对战后进入独立联机大厅；双方准备后自动进入棋盘页面。
- 单机练习弹窗可选阵营、人机难度，也保留同屏双人入口。
- 联机与人机对局始终将己方初始位置显示在下方；坐标、点击、走子动画随视角对应。同屏双人随行棋方翻转。
- 棋盘可返回房间，结束后在房间内再次准备。离开进行中的联机房间仍需确认并判负。刷新联机页面会恢复房间及阵营视角。

## 玩法

- 9 × 10 楚河汉界棋盘，传统象棋开局，红先。
- 红方与白色围棋为一方，黑方与黑色围棋为一方。
- 每步移动一枚象棋，或在空交叉点落围棋。围棋落下不能移动。
- 上下左右的己方象棋与围棋形成同一棋块，共享相邻空位的气；跨河连接，斜向不连接。
- 象棋使用传统走法，围棋可阻挡、蹩马腿、塞象眼和作炮架，也可被直接吃掉。
- 完成直接吃子后，同时提掉所有对方无气棋块；若已捕获对方将帅，立即获胜；否则此后己方仍有无气棋块的着法非法。禁止重复本局任何棋盘局面。
- 直接吃掉或围死将帅获胜；无合法行动判负。采用捕获将帅制，无必须应将限制；保留飞将吃子。
- PVP 为本机同屏双人。PVE 可选择红黑方及三档难度，选择黑方时电脑执红先行。人机悔棋撤回至玩家行动之前。

## 实现

`engine.js`：纯规则函数、气与提子、合法行动、精确的一步将帅威胁检查、局面评价和迭代加深的选择性 Alpha-Beta 搜索。

`ai.js`：独立计算线程。所有难度优先直接获胜，并遍历全部合法根节点，存在安全着法时排除一步丢将的着法。评估考虑象棋子力、活动度、过河兵、受攻击子力与棋块气数；新增围棋不获得免费子力奖励。入门最多搜索 2 层 / 650ms，标准 4 层 / 2200ms，进阶 5 层 / 5000ms，实际完成深度视局面和设备而定。非紧急局面使用候选剪枝，因此不是全宽搜索或专业棋力引擎。

`app.js` / `style.css`：响应式交互、棋谱、规则说明、悔棋、移动动画、吃子与将军提示。本地 PVP / PVE 对局保存在当前页面内存，刷新重置。联机对局保存在服务器内存，同一标签页刷新会恢复身份和房间。

字体可选从 Google Fonts 加载；不可访问时自动使用本机中文字体。

## 直接操作与声音

未选中象棋时，悬停空交叉点预览己方围棋（禁手位置以红边淡色显示），点击落子。点击己方象棋显示合法走位；下一次点击合法位置行棋，点击任何非法位置取消选中。触屏直接点击即可，键盘支持 Enter / 空格落子与 Esc 取消选择。

象棋移动采用 280ms 动画，系统减少动态效果设置下跳过。动画或 AI 思考期间锁定棋盘输入，悔棋和重开会取消旧动画或计算结果。

`audio.js` 使用 Web Audio 在本地合成原创五声音阶循环配乐（拨弦与笛音），并提供移动、落子、吃子、将军和胜利音效。打开页面时立即尝试播放配乐；若浏览器拦截有声自动播放，则在首次点击或键盘操作后恢复；可独立关闭配乐、音效和调节配乐音量。页面隐藏时暂停音频。无需下载音乐，不是传统曲目录音。

将军提示通过完整规则检查对方下一步能否直接捕获或围死将帅。提示不改变原有捕获将帅制，不强制应将。

象棋外圈以阵营标识：红方白圈、黑方黑圈，与同阵营围棋颜色一致。炮架不分敌我，双方象棋与围棋均可作炮架，吃子必须同行或同列且中间恰好一子。



## 用户系统与安全

- **用户通行证与安全认证**：
  - **注册账号**：自定义 2-16 位棋名，支持标准密码管理器（autocomplete）与现代异步 scrypt 密码哈希（记录算法版本与成本）。
  - **游客模式**：由服务端生成高熵随机凭据，禁止使用 IP 作为凭据或身份回退；不同浏览器上下文获得独立身份，同一浏览器可凭借安全凭据恢复原游客。游客可在个人中心随时升级为注册账号，完整继承个人战绩与历史。
  - **安全会话**：废除前端自制密码加密保存，采用服务端签发的高熵会话与 `HttpOnly; SameSite=Lax` Cookie 保持登录（数据库仅保存令牌 SHA-256 哈希），具备 7 天空闲超时与 30 天绝对有效期，退出、改密或权限变更时立即吊销。
  - **CSRF 纵深防护**：校验 Origin / Referer 来源白名单，并对所有基于 Cookie 的状态变更请求强制校验 `X-CSRF-Token`。
- **个人资料与数据生命周期**：
  - 头像支持预设经典印章或限制格式与尺寸（<=200KB）的本地上传图片，彻底禁止第三方外部 HTTP/HTTPS 图片 URL，杜绝 SSRF 风险。
  - **数据导出**：支持用户自主导出个人资料与已归档对局棋谱（JSON 格式，不含任何密码哈希或内部凭据）。
  - **自主注销**：支持用户经密码校验后注销账号，注销后个人历史对局自动匿名化保留（标记为“已注销玩家”），对手对局与胜率不受损。
- **管理员安全与审计中心**：
  - 采用**默认拒绝**的权限模型（主管理员 10000001 拥有全部权限，其他管理员仅在显式授权时生效）。
  - 生产环境严禁使用默认初始密码（`admin123`）；支持通过 `node users.js --reset-admin` 安全重置管理员凭据。
  - 敏感管理操作（删除账号、重置他人密码、变更管理员角色）须输入当前管理员密码二次认证。
  - 全流程操作审计（`audit_logs` 表），可在管理面板中实时查阅操作者、目标账号、操作类型、时间、详情与 IP 地址。

## 联机大厅

从主菜单选择联机对战进入大厅。玩家名和房间名由服务器随机生成。默认最多同时存在 5 个房间（管理员可配置 1–100 间），每间 2 人；双方准备后服务器随机分配红黑方并以标准布局开局。红先，支持取消准备、对局结束后重新准备。

服务器校验每一步的身份、阵营、回合、局面版本、走法、自杀禁手与禁同形；客户端不能自行宣布胜负或修改对手棋子。联机模式禁用本地悔棋与重开，防止单方面改变对局。

主动退出立即离房；对局中退出判负。断线时暂停，保留座位约 30 秒，同一标签页重连恢复对局；超过宽限期自动离房。最后一位玩家离房后立即删除房间。未开局的玩家断线会取消其准备状态。进入第二位玩家不会取消第一位已准备状态。

玩家身份凭据保存在本地持久化存储（localStorage，支持掉线、刷新或关闭网页后重连恢复）。测试两个人对战请使用不同浏览器或独立无痕/隐私窗口。

## 部署

详见 [DEPLOY.md](DEPLOY.md)。可用 `npm start` 或 `docker compose up -d --build` 启动。默认监听 `0.0.0.0:5173`，支持 `HOST`、`PORT`、`PUBLIC_ORIGIN` 环境变量。

**当前为单进程、内存房间版本**：服务重启会清空房间和棋局。不要用多个 Node worker / 多容器副本运行同一大厅；需要多实例或重启保留对局时，应先增加共享存储和跨进程消息层。

## 独立管理中心与数据存储

管理员从个人资料页打开独立的 `/admin.html` 页面（新标签页，原棋局连接继续保留）。包含“账号与权限”、“对局档案”、“服务器设置”以及“操作审计日志”四大管理板块：

- **账号管理**：后台仅支持创建正式注册账号（游客账号由客户端动态生成）；编辑用户名、账号角色与细粒度权限；重置密码；支持永久或限时封禁与解封。禁止将正式账号降级为无凭据的游客账号。敏感操作（改密、改权、删号）需输入当前管理员密码进行二次认证。
- **登录入口**：服务器设置可分别开放或关闭用户注册与游客登录。关闭游客登录后不再创建或重新登录游客账号，已有有效会话可继续使用。
- **权限边界**：主管理员 ID `10000001` 拥有完整权限且受底层保护不可删除或降级；次级管理员默认拒绝所有权限，仅能由主管理员显式授予。管理员不可授予超出自身权限范围的能力。
- **数据存储（SQLite）**：
  - 基于 Node.js 22 内置 SQLite 引擎（WAL 模式 + 外键约束），数据库文件位于 `./data/xiangqi.db`（或由 `DATABASE_PATH` 指定）。
  - 账号、凭据、会话、游客认证、对战档案、参赛人关系、系统设置和审计日志合理分表存储，支持服务端分页、搜索与筛选。
  - **安全迁移**：首次启动或检测到旧版 `users.json`（支持数组或对象格式）时自动完成事务化迁移，并在导入前生成安全备份 `users.json.bak.<时间戳>`。重复执行自动忽略已导入数据，失败自动回滚，原始数据与备份不被自动删除。
- **对局档案与结算**：场数、胜率与逐手棋谱由服务端权威结算并幂等写入 SQLite。清除历史对局或删除账号时对手胜负完整保留，历史记录自动匿名化为“已清除玩家”或“已删除玩家”。
- **服务器设置**：注册开关与最大房间数保存在数据库，修改立即生效并跨重启保留。

## 对局界面、棋钟与消息

- 保留墨绿、米白与木纹棋盘主题。桌面左侧为棋盘及操作，右侧为双方信息与消息；700px 及以下依次显示双方信息、棋盘、操作、消息。
- 联机、PVE 和同屏 PVP 默认每方 10 分钟倒计时，剩余 30 秒变色提醒，时间耗尽判负。联机由服务端判定，客户端根据服务端时间显示；刷新不会重置棋钟。
- 联机任一玩家断线时暂停双方棋钟，显示服务端给出的 30 秒重连截止时间；重连成功后继续，超时离房并判负。服务重启仍会清空内存房间。
- 本地悔棋恢复到该步之前的棋钟；离开练习页面暂停本地计时。本地练习不跨刷新保存。
- 消息栏默认合并系统通知、落子记录、文字和表情，可筛选全部、聊天、对局记录及系统。聊天仅向同房间成员发送，最多 300 字，每秒最多一条，按纯文本显示。
- 房间消息保留最近 200 条；双方重新准备开局时清空消息。完整棋谱仍保存在当前对局记录中；聊天不写入账号历史档案或数据库。
- 棋盘下保留本地悔棋、重新开局，增加认输与求和入口（支持双方协商和棋，人机练习一键和棋，和棋不计入胜率）。联机不允许单方悔棋、重开。配乐、音效和音量收纳至对局设置。

本轮验证：42 项 Node 自动化测试全部通过，含棋钟轮转、断线暂停、超时只结算一次、重连截止、聊天隔离/去重/限流、求和协商及和棋不计入胜率。

### 更新代码后重启服务

修改 `server.js`、`lobby.js` 或 `users.js` 后，需要重启对应端口的 Node 服务，再刷新浏览器。静态页面会读取磁盘上的新文件，但已运行的 Node 进程不会自动重新加载后端模块。若新页面出现棋钟停在 10:00、聊天提示“不支持的操作”、消息栏没有系统或棋谱记录，应先检查是否仍运行旧服务。重启会清空内存房间和棋局，账号数据库保留；双方需重新入座。
